## 2. Шорткоды: что выводят и куда вставлять

Шорткод можно вставить: в блок **«Шорткод»** редактора страниц, в виджет **«Шорткод»** Elementor,
в текстовый виджет, в меню (через плагины) или прямо в PHP-шаблон темы:

```php
<?php echo do_shortcode( '[vl_account_icon]' ); ?>
```

### `[vl_auth]` — вход и регистрация в один шаг

Одна форма без вкладок: телефон → код из SMS → кабинет. Отдельной регистрации нет —
незнакомый номер регистрируется автоматически после верного кода.

**Куда:** отдельная страница «Вход». Создайте страницу → вставьте шорткод → укажите её в
**Личный кабинет → Личный кабинет → Страница входа**. После этого на неё будут вести все иконки и ссылки «войти».
Отлично работает и внутри попапа Elementor.

| Атрибут | Значение | Зачем |
|---|---|---|
| `redirect` | URL | куда отправить после входа (по умолчанию — в кабинет или на страницу, откуда пришёл) |
| `title` | текст | заголовок над формой |
| `notice` | текст | подсказка над формой |

```
[vl_auth redirect="/lichnyj-kabinet/" title="Вход"]
```

### `[vl_login]` и `[vl_register]` — синонимы `[vl_auth]`

Оставлены, чтобы не ломать уже расставленные на сайте шорткоды: оба выводят ту же
одношаговую форму. Отдельной формы регистрации в плагине больше нет.

### `[vl_lost_password]` — восстановление доступа

**Куда:** отдельная страница, если нужна прямая ссылка (в письме, в меню). В большинстве случаев не нужен:
эта форма уже встроена в `[vl_auth]` по ссылке «Забыли пароль?».

### `[vl_account]` — личный кабинет целиком

Шапка с именем и контактами, левое меню, содержимое выбранного раздела.

**Куда:** страница «Личный кабинет» → указать её в **Личный кабинет → Личный кабинет → Страница кабинета**.
Если такую страницу не создавать, плагин сам встроится в страницу «Мой аккаунт» WooCommerce.

Гостю на этой странице автоматически показывается форма входа — отдельную проверку делать не нужно.
На одной странице с `[vl_auth]` его размещать не надо.

### `[vl_account_menu]` — только меню кабинета

**Куда:** сайдбар, футер, мобильное меню — если хотите меню отдельно от содержимого.
Атрибуты: `class`, `icons="yes|no"`.

### `[vl_account_icon]` — иконки в шапке

Гость видит человечка → ведёт на страницу входа.
Авторизованный видит человечка → кабинет и стрелку → выход (с подтверждением).
Это и есть задача «поменять местами иконки».

**Куда:** Elementor → **Theme Builder → Header** → виджет «Шорткод»; в мобильное меню; в хук шапки темы.

| Атрибут | По умолчанию | Зачем |
|---|---|---|
| `size` | `20` | размер иконок в пикселях |
| `show_logout` | `yes` | показывать ли стрелку выхода |
| `show_label` | `no` | подпись рядом с иконкой |
| `label_in` | `Личный кабинет` | подпись для авторизованного |
| `label_out` | `Войти` | подпись для гостя |
| `class` | — | свой CSS-класс |

```
[vl_account_icon size="22" show_label="yes" label_out="войти"]
```

У иконки есть атрибут `drawer="yes"` — тогда гость не уходит на страницу входа,
а получает ту же выдвижную панель справа, что и при попытке купить:

```
[vl_account_icon drawer="yes"]
```

### `[vl_wishlist_button]` — кнопка «в избранное»

**Куда:** шаблон карточки товара (Elementor → Theme Builder → Single Product) или карточка в каталоге.
Альтернатива без шорткода: галочка **«Кнопка «в избранное» в карточке»** в настройках — кнопка добавится
на страницу товара автоматически. Если на сайте уже есть своё сердечко — галочку не включайте.

Атрибуты: `product_id` (по умолчанию — текущий товар), `text="yes|no"` (скрыть подпись), `class`.

### `[vl_wishlist_count]` — счётчик избранного

Число товаров в избранном, обновляется по AJAX при клике на сердечко. **Куда:** рядом с иконкой избранного в шапке.

### `[vl_user_name]` — имя покупателя

**Куда:** приветствие в шапке или в попапе. Атрибут `fallback="Гость"` — что показать неавторизованному.

## 2.0. Как устроен вход в один шаг

Вход и регистрация — одно действие. Посетитель вводит телефон, получает код и попадает
в кабинет. Если номера в базе нет, аккаунт создаётся автоматически — заполнять анкету не нужно.

Над полем телефона стоит поясняющий текст, под кнопкой — строка про согласие
(оба меняются в настройках). Согласие на обработку персональных данных фиксируется
самим фактом нажатия кнопки, согласие на рекламные рассылки — отдельной необязательной
галочкой, которую можно убрать из формы.

**Откуда в кабинете берутся остальные данные:**

| Данные | Когда появляются |
|---|---|
| Телефон | сразу при входе, подтверждён кодом |
| Имя и фамилия | из первого оформленного заказа |
| Адрес доставки | из заказа (WooCommerce сохраняет их в профиль) |
| E-mail | из заказа, **но только после подтверждения по ссылке из письма** |

**Как работает подтверждение e-mail.** Покупатель указал почту при оформлении заказа →
ему уходит **два письма**: сначала стандартное письмо WooCommerce о заказе,
затем отдельное письмо со ссылкой «Подтвердить e-mail». Пока по ссылке не перешли,
адрес хранится «в ожидании» и к аккаунту не привязан — так нельзя записать на себя
чужую почту и получить доступ к чужим заказам. После перехода по ссылке адрес
становится почтой аккаунта, к кабинету подтягиваются прошлые заказы с этим адресом,
и по нему работает восстановление доступа.

В кабинете, в разделе «Мои данные», неподтверждённый адрес показан плашкой
с кнопкой «Отправить письмо ещё раз». Смена почты вручную идёт по тому же пути:
адрес меняется только после перехода по ссылке из письма.

В форме оформления заказа технический адрес вида `79261234567@phone.вашсайт.ru`
никогда не подставляется — поле e-mail остаётся пустым, чтобы покупатель вписал настоящую почту.

Отключается всё это на вкладке **«Заказы и письма» → «Подтверждение e-mail из заказа»**,
там же настраивается срок жизни ссылки.

### Письмо с подтверждением не приходит

Почти всегда дело не в плагине, а в том, что сайт вообще не умеет отправлять почту.
WordPress по умолчанию шлёт письма функцией PHP `mail()` с адреса вида `wordpress@сайт.ru`,
а Gmail, Яндекс и Mail.ru такие письма **молча отбрасывают** — они не попадают даже в «Спам».

Как разобраться за минуту:

1. **Личный кабинет → Диагностика → «Отправить тестовое письмо»** — введите свой адрес.
   - Ошибка сразу («Сайт не смог отправить письмо») — почта с сайта не уходит совсем,
     обычно на хостинге отключена `mail()`.
   - «Письмо принято к отправке», но письмо не пришло — сервер отдал письмо,
     а почтовый сервис получателя его отбросил.
2. В обоих случаях лечение одно: поставить **SMTP-плагин** (например, WP Mail SMTP)
   и отправлять с реального ящика на вашем домене, у которого настроены SPF и DKIM.
   После этого начнут доходить и письма WooCommerce о заказах.
3. Строка **«Отправка почты»** в диагностике показывает, с какого адреса уходят письма
   и подключён ли SMTP.
4. **Журнал** внизу вкладки «Диагностика» пишет каждую неудачную отправку с текстом ошибки
   от почтового сервера.

Плагин при этом не обманывает: если письмо не ушло, покупатель видит честное сообщение,
отметка об отправке не ставится, и кнопка «Отправить письмо ещё раз» остаётся рабочей.

**Привязать адрес вручную**, пока чинится почта: откройте пользователя в
**Пользователи → профиль → блок «Личный кабинет (VL Account)»** — там будет
ожидающий адрес и галочка «Подтвердить этот адрес вручную».

## 2.0.1. Адреса доставки и оплаты в разделе «Мои данные»

В кабинете, под контактами, выводятся два блока полей — те же самые, что и на оформлении заказа:

* **«Данные для заказа»** — плательщик: имя, компания, страна, регион, город, улица, индекс;
* **«Адрес доставки»** — если везти нужно на другой адрес.

**Данные подставляются сами.** Сначала берётся то, что уже сохранено в профиле покупателя,
а если поле пустое — значение из его последнего заказа (в адрес доставки при этом
подставляется адрес оплаты). Покупателю, который заказывал гостем и вошёл по SMS, останется
только проверить поля. Эти же данные потом подставляются в пустые поля оформления заказа.

Состав полей задаёт сам WooCommerce: сменил страну — поменялся набор полей и список регионов.
Индекс и обязательные поля проверяются при сохранении, ошибка подсвечивает нужное поле.
Сохранённый адрес пишется в покупателя WooCommerce, поэтому виден и в заказе, и в CRM.

**Как выключить:** *Личный кабинет → Личный кабинет* → «Адрес в разделе „Мои данные“»
(и отдельно «Отдельный адрес доставки»). Без блока в разделе останется ссылка на стандартную
страницу адресов WooCommerce, как было раньше.

Телефон и e-mail в этих блоках не дублируются — они редактируются выше, в контактах кабинета.

## 2.1. Вход перед покупкой (панель справа)

Гость доходит до покупки и упирается в форму входа: справа на всю высоту экрана выезжает
панель с той же формой входа/регистрации по SMS, что и в шорткоде. После входа
**прерванное действие продолжается само** — посетитель не начинает заново.

**Как включить:** *Личный кабинет → Вход и регистрация → блок «Вход перед покупкой»* →
галочка «Требовать вход перед покупкой». Там же — заголовок, текст панели и **шаг**,
на котором спрашиваем вход.

### На каком шаге спрашивать вход

| Режим | Что происходит | Когда выбирать |
|---|---|---|
| **При оформлении заказа** (по умолчанию) | Гость свободно кладёт товары в корзину, видит боковую корзину темы и итог. Вход требуется на кнопке «Оформить заказ» и на самой странице оформления. Корзина при этом сохраняется | Почти всегда: покупатель успевает увидеть цену и доставку до того, как у него спросят телефон |
| **При добавлении в корзину** | Вход нужен ещё до того, как товар попадёт в корзину | Если корзина должна быть только у зарегистрированных |

**Что перехватывается в режиме «при оформлении»:** `.checkout-button`,
`.wc-proceed-to-checkout a`, `.wc-block-cart__submit-button`, `.elementor-button--checkout`
(боковая корзина Elementor), `.xoo-wsc-ft-btn-checkout`, любой элемент с атрибутом
`data-vl-requires-auth` — и **любая ссылка на страницу оформления заказа**, как бы её ни
назвала тема.

**Что перехватывается в режиме «при добавлении»:** `.single_add_to_cart_button`,
`.custom-buy-now-button`, `.add_to_cart_button`, `.ajax_add_to_cart`, кнопка блочного
каталога и `data-vl-requires-auth`.

В обоих режимах свои кнопки темы добавляются селекторами в поле «Дополнительные кнопки».

**Три уровня защиты**, чтобы обойти было нельзя:

1. Перехват клика в браузере (на фазе захвата — раньше обработчиков темы и WooCommerce).
2. Серверная проверка. В режиме «при оформлении» гость, пришедший на страницу оформления
   по прямой ссылке или с выключенным JS, возвращается в корзину с уже открытой панелью,
   а после входа попадает обратно на оформление. В режиме «при добавлении» перехватывается
   ссылка `?add-to-cart=…`.
3. WooCommerce не примет заказ от гостя: в режиме «при оформлении» включается его
   собственный запрет гостевого оформления — это закрывает и блочное оформление,
   и Store API. В режиме «при добавлении» работает проверка
   `woocommerce_add_to_cart_validation` и Store API.

**Адаптивность:** десктоп — панель 440 px справа, планшет — 400 px, телефон — на всю ширину
и высоту (`100dvh`, без «уезжающего» низа в iOS Safari). Прокрутка страницы под панелью
блокируется, закрытие — крестиком, кликом по затемнению и клавишей Esc, фокус заперт внутри панели.

Если панель нужна где-то ещё (например, по клику на «Оформить заказ»), повесьте на элемент
атрибут `data-vl-open-auth` — он откроет ту же панель.

### Если панель появилась внизу страницы без оформления

Значит, до неё не доехали стили плагина. Панель это переживает — критическое
оформление печатается прямо рядом с формой, а JavaScript при открытии проверяет,
действительно ли панель закреплена на экране, и при необходимости чинит позиционирование сам.
Но причину лучше устранить, иначе на сайте будут «плавать» и остальные стили:

1. **Плагин оптимизации.** Autoptimize, WP Rocket, LiteSpeed, Perfmatters, WP Fastest Cache —
   опции «объединить CSS/JS», «минифицировать», особенно **«удалить неиспользуемый CSS»**.
   Добавьте `vl-account.css` и `vl-account.js` в исключения. Это самая частая причина.
2. **Кеш.** После обновления плагина очистите кеш сайта и кеш браузера (Ctrl+F5).
   Версия файлов теперь меняется автоматически при каждом обновлении, но уже
   собранные объединённые файлы надо пересобрать вручную.
3. **Проверка.** *Личный кабинет → Диагностика* → строка «Стили и скрипты плагина»:
   там ссылка на `vl-account.css`. Откройте её — должен открыться текст стилей, а не 404.
   Там же плагин предупредит, если найдёт на сайте оптимизаторы.

Отключить гейт программно для отдельных случаев:

```php
add_filter( 'vlacc_gate_should_block', function ( $block ) {
    return is_product_category( 'podarochnye-sertifikaty' ) ? false : $block;
} );
```

## 3. Настройка SMS в админке

Меню **«Личный кабинет»** → вкладка **«SMS.RU»**.

### Поля вкладки

| Поле | Что вписать |
|---|---|
| **api_id** | Ключ из кабинета SMS.RU (главная страница, блок «Ваш api_id»). Ключ с вашего скриншота засвечен — нажмите там «Изменить» и вставьте новый |
| **Имя отправителя** | Только **согласованное** с операторами имя из раздела «Отправители». Пока не согласовано — оставьте пустым, сообщения уйдут от общего имени SMS.RU. Несогласованное имя = ошибка 204, код не уйдёт |
| **Как отправлять код** | `Звонок` — SMS.RU звонит, код = последние 4 цифры номера звонящего. Дешевле, мгновенно, имя отправителя не нужно. `SMS с кодом` — классика. `Сначала звонок, если не вышло — SMS` — самый надёжный |
| **Текст SMS** | `{code}` — код, `{site}` — название сайта. Держите текст коротким: кириллица режется по 70 символов, длиннее = дороже. Хороший вариант: `Код для входа: {code}` |
| **Тестовый режим** | Запросы уходят с `test=1`: SMS.RU отвечает как обычно, но сообщение не отправляется и деньги не списываются. Для проверки формы. На рабочем сайте — выключить |
| **Показывать код на экране** | Код выводится прямо в форме. Только для отладки на тесте, на боевом сайте это дыра — плагин ругается на это в «Диагностике» |

### Ограничения отправки (защита баланса)

| Поле | Рекомендую | Смысл |
|---|---|---|
| Длина кода | 4 | для режима «Звонок» всегда 4 — это цифры номера |
| Срок жизни кода, сек | 300 | 5 минут |
| Пауза между отправками, сек | 60 | защита от «долблю кнопку» |
| Попыток ввода кода | 5 | после — код сгорает |
| Кодов на номер в сутки | 10 | защита от накрутки на один номер |
| Кодов с одного IP в час | 15 | защита от бота, который сливает баланс |

### Вкладка «Диагностика»

- **Подключение к SMS.RU** — показывает баланс. Видите сумму — ключ верный и связь есть.
- **Имя отправителя** — плагин запрашивает у SMS.RU список согласованных имён того аккаунта,
  которому принадлежит `api_id`, и сверяет с настройкой. Имя есть в списке — плагин отправляет
  именно его; имени нет — строка станет красной и покажет, какие имена у ключа на самом деле.
- **Отправить тестовый код** — введите свой номер, проверьте доставку (в режиме «Звонок» покажет ожидаемый код).
- **Обновить постоянные ссылки** — если разделы кабинета отдают 404.
- **Журнал** — последние события: что ушло, что не ушло и с какой ошибкой.

### Что настроить на стороне SMS.RU

1. **Пополнить баланс.** На вашем скриншоте 10 ₽ — это 2–3 SMS. Звонок дешевле SMS, при потоке регистраций разница заметная.
2. **Дневной лимит** «0 из 50» — при росте трафика поднять через «Увеличить лимит», иначе на 51-й регистрации коды перестанут уходить.
3. **«Только в дневное время: нет»** — так и оставить, иначе ночные коды не дойдут.
4. **Согласовать отправителя** — если хотите фирменное имя в SMS вместо общего.

### Если в SMS приходит чужое имя отправителя

Например, вместо согласованного имени абонент видит общее имя шлюза.
Разбираться по шагам:

1. **Диагностика → «Имя отправителя»**. Плагин показывает, какие имена согласованы у аккаунта,
   которому принадлежит указанный `api_id`. Красная строка = ключ от другого аккаунта
   (или субаккаунта), либо в имени опечатка — например, кириллическая «о» вместо латинской.
   Плагин сравнивает без учёта регистра и лишних пробелов, но букву-двойник видит.
2. **Журнал плагина**. У каждой отправки записаны имя отправителя, которое ушло в запросе,
   и `sms_id` сообщения.
3. **SMS.RU → «Отчёты»**, найти сообщение по этому `sms_id`. Там видно, с каким именем
   сообщение реально ушло в сеть оператора:
   * в отчёте ваше имя, а на телефоне другое → подмена у оператора или на маршруте;
     это вопрос к поддержке SMS.RU (частая причина — маршрут для кодов подтверждения
     через общий канал, где имя отправителя фиксированное);
   * в отчёте общее имя → сообщение отправлено без вашего имени: проверьте, тот ли ключ,
     и нет ли у аккаунта своей подмены отправителя;
   * сообщения нет в отчётах вовсе → SMS отправил не этот плагин, а что-то другое на сайте.

### Порядок первого запуска

1. Вставить `api_id` → сохранить.
2. «Диагностика» → убедиться, что виден баланс.
3. Способ доставки = **Звонок** → сохранить.
4. «Отправить тестовый код» на свой номер.
5. Открыть страницу входа в режиме инкогнито и пройти регистрацию целиком.
6. Выключить «Тестовый режим» и «Показывать код на экране».
