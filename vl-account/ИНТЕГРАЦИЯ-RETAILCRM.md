# VL Account × Simla.com (RetailCRM) — как связаны плагины

Документ описывает связку плагина **VL Account** с официальным плагином
**Simla.com** (`woo-retailcrm`): что куда передаётся, где это настраивается
и что проверить, если данные не сходятся.

Важно: плагин `woo-retailcrm` **не изменялся**. Вся логика связки лежит в
`vl-account/includes/integrations/` и работает через публичные классы Simla
(`WC_Retailcrm_Proxy`, `WC_Retailcrm_Loyalty`, `WC_Retailcrm_Customers`) и
стандартные хуки WordPress. Если плагин Simla выключить, кабинет продолжит
работать на локальных данных — ничего не сломается.

---

## 1. Что делает связка

| Область | Было | Стало |
|---|---|---|
| Покупатель в CRM | Simla выгружает покупателя на `user_register` — до того, как кабинет записал телефон. В CRM уезжал клиент без номера | Кабинет досылает телефон, имя и согласия сразу после регистрации |
| Технический e-mail | При входе по SMS кабинет заводит адрес `79001234567@phone.сайт`, и он попадал в CRM | Такой адрес в CRM не отправляется, покупатель уезжает с телефоном |
| Подписка | Галочка «хочу получать письма» жила только в WordPress | Управляет полем «подписан» у покупателя в CRM |
| Заказ гостя | Кабинет привязывал заказ к аккаунту **после** выгрузки — в CRM заказ оставался гостевым | Кабинет привязывает заказ **до** выгрузки (приоритет хука 5 против 10 у Simla) |
| Бонусы в кабинете | Раздел «Бонусы» показывал локальный баланс из метаполя | Баланс, уровень, сгорание, ожидаемые начисления и история берутся из программы лояльности CRM |
| Вступление в ПЛ | Отдельный раздел Simla «Loyalty program» со своей вёрсткой | Вступление, активация и подтверждение по SMS — в разделе «Бонусы» в оформлении кабинета. Дублирующий пункт меню убран, его адрес ведёт на «Бонусы» |
| Промокод за регистрацию | Флаг «только один купон в заказе» выкидывал из корзины купон списания баллов | Флаг снимается: промокод и баллы работают вместе |
| Служебные купоны | Купоны `loyalty12345`, которые Simla создаёт для списания, попадали в список промокодов кабинета | Скрыты |
| Купон и техническая почта | Купон списания привязан к почте покупателя; для входа по SMS почта техническая, и купон становился неприменимым | Ограничение по техническому адресу снимается |
| Списание баллов в корзине | Служебная таблица Simla с инлайновыми стилями | Блок в оформлении кабинета: баланс, максимум, списание и отмена |
| Начисление за заказ | Строка «Points will be awarded…» под способами оплаты | Строка «Начислим баллов» рядом с итогом заказа |
| Избранное | Только в кабинете | Выгружается в пользовательское поле покупателя в CRM (если код поля указан) |
| Адрес покупателя | Правился на отдельной странице WooCommerce | Правится в разделе «Мои данные». Сохраняется через `WC_Customer`, поэтому Simla подхватывает изменение своим штатным хуком `woocommerce_update_customer` и адрес уезжает в CRM |

## 2. Настройка

### Шаг 1. Настроить сам плагин Simla

**WooCommerce → Настройки → Интеграция → Simla.com**:

1. Адрес API и ключ API.
2. Включить **программу лояльности** (без этого раздел «Бонусы» покажет локальный баланс).
3. Включить купоны WooCommerce (**WooCommerce → Настройки → Общие → Включить использование купонов**) —
   без них Simla физически не сможет списать баллы.
4. В блоке полей заказа выбрать поле для **промокодов** — тогда в CRM будет видно,
   каким кодом воспользовался покупатель.

### Шаг 2. Проверить связку

**Личный кабинет → Simla / RetailCRM**. В верхней таблице сразу видно:

* активен ли плагин Simla;
* отвечает ли CRM на ключ API и какой магазин (`site`) выбран;
* включена ли программа лояльности;
* включены ли купоны;
* настроено ли поле для промокодов и поле для избранного.

Те же строки продублированы во вкладке **Диагностика**.

### Шаг 3. Настроить поведение

Все переключатели — на вкладке **Simla / RetailCRM**.

| Настройка | По умолчанию | Смысл |
|---|---|---|
| Включить интеграцию | вкл | Общий выключатель. Выключено — кабинет не обращается к CRM |
| Досылать данные покупателя | вкл | Телефон, имя и согласия уходят в CRM после регистрации |
| Согласие на рассылку → подписка | вкл | Галочка в кабинете управляет полем «подписан» |
| Не отправлять технические адреса | вкл | Адреса `@phone.*` в CRM не уезжают |
| Привязывать заказ до выгрузки | вкл | Кабинет обрабатывает заказ раньше Simla |
| Поле CRM для избранного | пусто | Символьный код пользовательского поля покупателя |
| Кэш данных лояльности | 300 сек | Баланс и история кэшируются, чтобы не дёргать API на каждой странице |
| Источник баланса баллов | авто | авто / только CRM / только локальный баланс |
| Вступление и активация в кабинете | вкл | Формы ПЛ в разделе «Бонусы» |
| Убрать раздел Simla из меню | вкл | Прячет дубль «Loyalty program» и перенаправляет его адрес |
| Списание баллов в корзине | вместо блока Simla | вместо / дополнительно / не выводить |
| Начисление рядом с итогом | вкл | Переносит строку «начислим баллов» к сумме заказа |
| Промокод совместим с баллами | вкл | Снимает с промокода флаг «только один купон» |
| Прятать служебные купоны | вкл | `loyalty12345` не показываются в «Промокодах» |
| Чинить купоны с техническим адресом | вкл | Снимает нерабочее ограничение по почте |

## 3. Как это выглядит для покупателя

### Раздел «Бонусы»

Раздел сам определяет состояние участия:

1. **Участия нет** — форма «вступить в программу». Телефон подставляется из кабинета
   (он уже подтверждён кодом при входе), галочки согласий появляются, если тексты
   заполнены в настройках Simla.
2. **Участие есть, но не активировано** — кнопка «активировать». Если CRM просит
   подтверждение, тут же появляется поле для кода из SMS (код отправляет CRM, не SMS.RU).
3. **Участие активно** — баланс, уровень, правила начисления, ближайшее сгорание,
   ожидаемые начисления, сумма покупок, сколько осталось до следующего уровня и история
   операций. Операции по заказам — ссылками на заказ в кабинете.
4. **Уровень со скидкой** (тип `discount`) — вместо баллов показывается процент скидки:
   такие уровни баллы не начисляют.

Кнопка «Обновить данные из CRM» сбрасывает кэш — полезно сразу после начисления менеджером.

### Корзина

Блок списания баллов показывает баланс, максимум для этой корзины (его считает CRM
методом `loyalty/calculate`), поле ввода и кнопку. После списания — сколько баллов
списано и ссылка «отменить». Ниже — сколько баллов начислят за заказ.

Механика намеренно повторяет плагин Simla: создаётся купон `loyalty<число>` на сумму,
равную числу баллов. Именно такой купон Simla снимает при создании заказа и превращает
в списание баллов в CRM. Поэтому обмен с CRM остаётся штатным.

Если тема использует **блочную корзину**, хук `woocommerce_cart_coupon` не срабатывает —
поставьте блок вручную шорткодом:

```
[vl_loyalty_cart]
```

## 4. Порядок обмена при оформлении заказа

```
woocommerce_checkout_order_processed
├─ 5   VL Account: находит или создаёт покупателя, привязывает заказ, подтягивает гостевые заказы
├─ 10  Simla: снимает купон списания, считает скидку ПЛ, создаёт заказ в CRM
│        └─ заказ уже привязан к покупателю → в CRM уезжает клиент, а не гость
└─ 20  (свободно)
```

Без интеграции кабинет работал на приоритете 20 — то есть после выгрузки. Переключатель
«Привязывать заказ до выгрузки» возвращает старое поведение, если оно зачем-то нужно.

## 5. Точки расширения

Хуки, добавленные для связки (можно использовать в теме или своём коде):

| Хук | Тип | Назначение |
|---|---|---|
| `vlacc_checkout_hook_priority` | фильтр | Приоритет обработки оформленного заказа кабинетом |
| `vlacc_promo_individual_use` | фильтр | Флаг «только один купон» у промокода за регистрацию |
| `vlacc_consents_saved` | действие | Согласия сохранены: `($user_id, $consents)` |
| `vlacc_crm_customer_data` | фильтр | Данные покупателя перед отправкой в CRM: `($data, $user_id, $customer)` |
| `vlacc_loyalty_charged` | действие | Баллы списаны в корзине: `($user_id, $amount)` |
| `vlacc_bonus_balance` | фильтр | Баланс баллов (интеграция подменяет его данными CRM) |
| `vlacc_bonus_history` | фильтр | История операций |

## 6. Если что-то не сходится

**В разделе «Бонусы» пусто, хотя в CRM баллы есть.**
Проверьте вкладку **Simla / RetailCRM**: связь с CRM, включённую программу лояльности
и то, что покупатель существует в CRM с `externalId`, равным ID пользователя WordPress.
Кабинет ищет участие именно по нему.

**Баланс отстаёт.**
Данные кэшируются (по умолчанию 5 минут). Нажмите «Обновить данные из CRM» или уменьшите
время кэша. Кэш сбрасывается сам при смене статуса заказа, вступлении в программу,
активации и списании баллов.

**Списание баллов не появляется в корзине.**
Причины по порядку: участие не активировано; уровень даёт скидку, а не баллы (тогда
списывать нечего); CRM вернула нулевой максимум для этой корзины; выключены купоны
WooCommerce; тема использует блочную корзину — поставьте `[vl_loyalty_cart]`.

**Промокод выкидывает баллы из корзины.**
Включите «Промокод совместим с баллами». Уже выданные промокоды нужно поправить вручную:
**Маркетинг → Купоны → Использование → снять «Индивидуальное использование»**.

**В CRM покупатели без телефона.**
Включите «Досылать данные покупателя». Уже выгруженных покупателей проще обновить
массово: **WooCommerce → Настройки → Интеграция → Simla.com → выгрузка клиентов**.

**В CRM покупатели с адресами `@phone.сайт`.**
Включите «Не отправлять технические адреса». На уже выгруженных записях адрес останется —
его нужно чистить в CRM.
